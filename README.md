# NEXLAB

Каталог електронних компонентів і DIY-проєктів. Для GitHub Pages можна підключити Firebase Authentication і Firestore за інструкцією нижче; сервер Node.js потрібен для автоматичного резервування залишків і перевірки замовлень.

## Структура проєкту

```text
frontend/                 сайт, сторінки та всі браузерні ресурси
  admin/                  панель керування
  api/                    клієнтські сервіси даних та авторизації
  assets/images/products/ фотографії товарів
  css/                    стилі
  guides/                 прошивки для навчальних проєктів
  js/                     логіка інтерфейсу
backend/server/           локальний Node.js API та сервер
firebase/                 правила Firestore
scripts/                  службові скрипти та їхні дані
tests/                    автоматичні перевірки
data/                     локальна SQLite-база (не потрапляє до Git)
```

У корені залишаються лише файли запуску, налаштувань і головна документація. HTML-сторінки зібрані у `frontend/`; workflow публікує саме цю папку. Один раз у GitHub відкрий **Settings → Pages → Build and deployment → Source** і вибери **GitHub Actions**.

## Локальний запуск

1. Встанови Node.js 24 або новішої версії.
2. У терміналі PowerShell відкрий папку проєкту.
3. Запусти:

   ```powershell
   npm start
   ```

4. Відкрий <http://127.0.0.1:8767>.

Не відкривай `frontend/index.html` подвійним кліком: браузер блокує JavaScript-модулі з `file://`. Дані локальної версії зберігаються у `data/nexlab.sqlite`; папка не додається до Git.

## Firebase для облікових записів на GitHub Pages

GitHub Pages не запускає Node.js, але для реєстрації та входу можна підключити Firebase Authentication. Увімкни в Firebase Console спосіб входу «Електронна пошта/пароль», створи Cloud Firestore і опублікуй правила з `firebase/firestore.rules`. Додай домен GitHub Pages до списку дозволених доменів Firebase Authentication.

Зареєструй вебзастосунок у Firebase Console й перенеси його Web config у `frontend/js/firebase-config.js`. Ця конфігурація містить публічні ідентифікатори застосунку; приватний service-account key у браузер не додавай.

Поки конфігурація Firebase порожня, локальний Node.js-режим лишається активним. Після підключення Firebase реєстрація, вхід, профіль, зміна пароля, каталог, DIY-проєкти, особиста майстерня, відгуки, оформлення замовлень і панель керування працюють через Firestore. Роль адміністратора призначається вручну в `users/{uid}` у Firestore. Замовлення через GitHub Pages зберігаються як заявки: перед підтвердженням адміністратор має перевірити ціни й залишки, оскільки без захищеного сервера сайт не може безпечно перевірити склад і списати товар. Для автоматичного резервування залишків і серверної перевірки замовлень використовуй Node.js сервер.

## Серверні налаштування

Сервер слухає `127.0.0.1:8767` за замовчуванням. При першому запуску скопіюй `.env.example` у `.env`, задай власні `ADMIN_EMAIL` і `ADMIN_PASSWORD` (щонайменше 10 символів) та виконай `npm start`. Сервер створить адміністратора і постійну SQLite-базу `data/nexlab.sqlite`. Файл `.env` і каталог `data` не додаються до Git.

У панелі `/admin/index.html` можна додавати товари, змінювати всі поля картки (назву, категорію, опис, ціну, залишок, бренд, характеристики, теги, ілюстрацію та фото за HTTPS-посиланнями) і видаляти позиції. Часткове оновлення ціни й залишку через API також підтримується. Товари каталогу зберігаються у SQLite та залишаються після перезапуску сервера.

Адміністратор може видати звичайному користувачу тимчасовий пароль у розділі «Користувачі». Новий пароль показується в панелі один раз — передай його власнику облікового запису безпечним способом; після входу користувач має змінити пароль у профілі. Статуси замовлень обмежені допустимими переходами: скасування до відправлення повертає товар на склад, а доставлене замовлення можна позначити поверненим лише після фактичного отримання товару.

Можна змінити `PORT`, `HOST` і `DATA_DIR`. На серверному хостингу встанови `HOST=0.0.0.0`, використовуй порт із `PORT`, а `DATA_DIR` спрямуй на постійне сховище. За HTTPS встанови `SECURE_COOKIES=true` і `PUBLIC_ORIGIN` з повним origin сайта, наприклад `https://shop.example`. GitHub Pages не запускає цей сервер і не підходить для збереження реальних замовлень чи облікових записів.

## Команди

- `npm start` — запустити локальний сайт і API.
- `npm test` — запустити автоматичні тести Node.js.
